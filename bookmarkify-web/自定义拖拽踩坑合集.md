# 自定义拖拽踩坑合集

记录 macOS 启动台式文件夹（vuuri/Muuri 跨网格拖拽 + 原位浮层卡片）开发过程中踩的坑。

> ⚠️ **本文描述的实现已不在代码库中。** 界面后来改成了 `pages/index.vue` 的文件夹卡片列表，`LaunchBoard.vue`/`LaunchCell.vue`/`cell/*`/`layouts/launch.vue` 变成无人引用的死代码，已于 2026-08-04 删除。
> 保留本文是因为其中的**坑**（FLIP 动画、命中判定、跨网格隔离、原生拖放的种种行为）仍然成立 —— 现存的 `components/BookmarkFolderCard.vue` 用的是同一套 Pragmatic DnD。文中提到的文件路径请当作历史记录读。

> 背景：vuuri 0.4.6（内含 Muuri 0.9.5）。主网格 `pages/index.vue`、文件夹卡片 `components/launchpad/FolderPanel.vue`。

## 1. `<style scoped>` 命不中 Muuri 动态节点
`FolderPanel.vue` 用 `<style scoped>`，而 `.muuri-item` / `.muuri-item-content` 是 Muuri 运行时动态创建的，**没有组件的 `data-v-xxx` scope 属性**，scoped 选择器（编译成 `.x[data-v-xxx]`）根本命不中 → 图标不居中、看起来"没有 gap"。
**正解**：用 `:deep(.muuri-item-content)`，或像 `index.vue` 那样用全局 `<style>`。

## 2. 遮罩"挡点击"与"跨网格拖拽"互斥
全屏遮罩若用 `pointer-events` 拦截点击（模态感），会**同时挡住"按住主网格图标往文件夹里拖"**（反向拖入），因为拖拽以 `mousedown` 在主网格元素上起手。
**正解**：遮罩 `pointer-events-none` 放行拖拽 + **捕获阶段 `click` 监听**拦截卡片外点击（`stopPropagation`+`preventDefault`+关闭）。click 在 press-release 无位移时才触发，不影响 mousedown 起手的拖拽。

## 3. `transform` 破坏 `backdrop-filter`
`<Transition>` 的 `scale()` 作用在带 `backdrop-filter: blur` 的遮罩层上时，毛玻璃会渲染成"死板镶嵌的一张图"。
**正解**：遮罩层只用 `opacity` 过渡，不要对它做 `transform`。

## 4. ⭐ vuuri 的 `dragContainer` 无法通过 `:options` 覆盖
`_setupOptions()` 内部：`muuriOptions = { ...generateDragOptions(), ...muuriOptions }` 之后又 `{ ...this.options, ...muuriOptions }`——`generateDragOptions()` 把 `dragContainer` 写死成网格元素且**后置覆盖**，所以从 `:options` 传 `dragContainer: document.body` **是无效的**。
**影响**：想让被拖元素"飞出"卡片，传 dragContainer 没用。
**正解**：让卡片祖先链**不裁剪**（`overflow: visible`），靠默认网格容器 + 无裁剪让被拖图标自然溢出（spike 即如此成立）；或 mount 后改 Muuri 实例的 `_settings.dragContainer`（hack，不推荐）。

## 5. 卡片 `overflow` 裁剪被拖出的图标
卡片为限制高度加了 `maxHeight + overflow-y:auto`，结果把"拖出卡片"的图标裁断（截图：恐龙图标在卡片下边缘被切）。且 **`overflow-y:auto` 会让 `overflow-x` 计算值也变成 `auto`**，水平方向一起裁。
**正解**：跨网格拖出要求祖先链无裁剪 → 去掉卡片的 `overflow`/`maxHeight`，卡片高度随内容。

## 6. Tailwind 任意值类在 throwaway 页面没生成
spike 页用 `size-[72px]` / `bg-red-300` 等任意值类时方块没尺寸没颜色（疑似内容扫描/生成问题）。
**正解**：临时验证页直接用内联 `style`，绕开 Tailwind 生成这一变量。

## 7. 大尺寸卡片不宜锚定到图标
55vw 的大卡片若锚定到左侧图标会贴左、向右铺开，看着像"定位错误"。
**正解**：大卡片**水平居中**，垂直方向跟随点击行并夹紧到视口内。

## 8. 本地验证环境限制
- 用户的 nuxt dev server 跑在 `:3000`（IPv6 `[::1]`），同目录 HMR 会自动加载新文件，直接刷新即可验证。
- Claude 的 Bash 沙箱**连不上 localhost**（curl 全返回 000，但 `lsof` 证实服务在跑）。
- Claude 浏览器扩展未连接，无法由 AI 自动做拖拽/视觉验证 → 关键视觉验证交由人工。

## 9. ⭐ 跨网格拖出时不能在源网格 `@send` 关闭/卸载弹窗
想做"拖出即关闭文件夹"，若在**源网格**（文件夹）的 `@send` 时刻 `close()` 卸载文件夹网格：此刻 vuuri group 的迁移**尚未完成**，卸载会破坏 `tt` 的 dragging item 状态，接收方 `_onItemReceive` 把 `null` push 进 `modelValue` → 渲染 `item.id` 时 `Cannot read properties of null` 崩溃。
**正解**：改在**接收方**（主网格）的 `@receive` 关闭文件夹。**但仍不能在 `@receive` 里同步关闭**——见下方补充。
**补充（再次踩坑）**：vuuri `_registerEvents` 里，转发给我们的 emit 处理器**注册早于内部 `_onItemReceive`**，所以我们的 `@receive` 回调先于内部迁移完成执行。若在此**同步**卸载文件夹，会打断迁移、让接收方把 `undefined` push 进 `modelValue` → `nodeById` 的 `new Map(...)` 抛 `Iterator value undefined is not an entry object` → 渲染崩 → 文件夹没正常关闭（蒙版卡死）。
**正解2**：`@receive` 里把关闭放到 `nextTick(() => visible=false)`，让内部迁移先完成；并给 `pageData`/`nodeById` 加 `.filter(Boolean)` 兜底，任何瞬时脏值都不致整页崩。
**附带**：跨网格拖出后，源网格的 `drag-release-end` 不再触发（释放发生在接收网格），依赖它复位的状态（如 `dragging`）会遗留；用接收方关闭 + 重开时 `watch` 复位可规避。

## 10. ⭐ 持久化的树 + 跨网格遗留重复 id = 刷新卡死
`bookmark.store` 的 `layoutNode` 被 `persist` 到 localStorage。跨网格移动若**两侧同步不彻底**（如拖出后源网格 `drag-release-end` 不触发、文件夹 `children` 未及时移除该项），同一 id 会**同时存在于根列表和某文件夹 children** → Vuuri `item-key` 重复 → 渲染异常/死循环；坏数据写进 localStorage 后，**刷新加载即卡死**，且后续每次刷新都卡。
**正解**：
1. 源头同步要彻底：拖出在主网格释放时从来源文件夹 children 移除该项 + 处理后端自动解散。
2. 兜底：`store.dedupeLayout()`（保留首次出现）+ `persist.afterHydrate` 调它，水合后立即去重，恢复历史坏数据、防卡死；随后 `update()` 拉后端权威数据校正。
**教训**：跨网格 + 本地多份列表（根 / 文件夹 localChildren / store children）极易不一致，凡是会持久化的树都要有去重兜底。

## 11. ⭐ 自研网格列数测量的循环依赖 → 全部挤成单列
重构后 `useGridLayout` 用 `containerRef.clientWidth` 算列数，而那个容器的宽度又被设成 `gridWidth = 列数 × 列宽`。于是：初始 `cols=1` → 容器宽=1 列 → 测出来还是 1 列 → **永远卡在单列**（截图：所有图标竖向堆成一列居中）。本质是"用被结果约束了宽度的元素去测量决定结果的输入"，自我锁死。
**正解**：测量与定位分离——外层放一个 `w-full` 的 wrapper（宽度 = 父级可用宽度，不受列数影响）用于测量算列数；内层才是 `width: gridWidth` 的定位网格。`useGridLayout` 观测 wrapper，拖拽命中/坐标用内层定位网格的 rect。文件夹浮层同理：wrapper 填满卡片内宽，列数即由卡片宽度决定。
**教训**：任何"容器尺寸 → 计算 → 又反过来设容器尺寸"的链路都要拆成两个元素，测量元素的尺寸必须独立于计算结果。

## 12. ⭐ 两条 CSS/事件「抑制原生拖拽」是 Pragmatic 的致命伤
Pragmatic DnD 的 element adapter **基于浏览器原生 HTML5 拖放（`dragstart`）工作**。手搓 pointer 方案时为防原生拖放加的两样东西，搬到 Pragmatic 上会让它**彻底启动不了**（症状：`pointerdown` 有、但无 `dragstart`，完全拖不动）：
1. `@dragstart.prevent`（模板上阻止 dragstart）；
2. cell 元素上的 `-webkit-user-drag: none`（CSS 禁止该元素被原生拖拽）。
**正解**：拖拽源（cell）**绝不能**加这两样。只在内部 `<img>` 上保留 `-webkit-user-drag:none; pointer-events:none`——目的是让拖拽源是整张 cell 而非图片，这反而是必要的。
**诊断招**：`pointerdown` 探针 + 全局 `dragstart` 捕获探针；看到「有 pointerdown、无 dragstart」即可锁定是「原生拖拽被抑制」这一类。
